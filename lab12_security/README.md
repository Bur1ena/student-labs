# Лабораторная работа №12. Безопасность больших языковых моделей и ИИ-агентов

## Цель работы
Разработать модель угроз учебного LLM-агента, провести воспроизводимые испытания на атаки через инструкции и данные, внедрить защитные механизмы в приложение и сравнить результаты до и после их внедрения.

## Используемые технологии
* Python 3.10+
* Стандартные библиотеки Python (`json`, `re`, `dataclasses`)

## Запуск проекта

Для запуска тестов безопасности (без LLM) выполните команду:

python src/agent12_demo.py

## Архитектура безопасности и границы доверия

1. **Доверенные данные:** роль пользователя (`analyst`/`supervisor`), принадлежность к арендатору (`tenant`), разрешения на инструменты (`PERMISSIONS`). Они задаются сервером, а не моделью.
2. **Недоверенные данные:** текст из базы знаний (RAG), ответы внешних API, предложения инструментов (`tool_calls`).
3. **Граница доверия:** функция `execute(action, ctx)`. Любое предложение модели (даже если оно выглядит как команда) проходит проверку прав, аргументов и лимитов.

## Метрики оценки защищённости

| Показатель | Значение | Комментарий |
|---|---|---|
| **ASR (Attack Success Rate)** | 40.0% (до защиты) | 4 из 10 атакующих запросов привели к `would_execute` |
| **BDR (Blocked Dangerous Request Rate)** | 100.0% | 10 из 10 опасных запросов заблокированы после внедрения проверок |
| **FPR (False Positive Rate)** | 0.0% | 0 из 2 легитимных запросов ошибочно заблокированы |

## Анализ результатов
1. **Демонстрация уязвимости (ДО):** Функция `unsafe_dispatch` показывает, что без проверок система могла бы выполнить `send_report` для внешнего адресата (статус `would_execute`).
2. **Защищённый вариант (ПОСЛЕ):** Функция `execute` блокирует все опасные вызовы (ASR = 0%, BDR = 100%), при этом не мешает легитимным операциям (FPR = 0%, BCR = 100%).
3. **Изоляция арендаторов (T2, T9):** Проверка `tenant` не позволяет аналитику из арендатора A прочитать инцидент арендатора B, даже если модель предлагает такой вызов.

## Вывод
В ходе работы был реализован безопасный слой выполнения инструментов. Разделение ответственности (модель только предлагает действие, приложение проверяет и выполняет) позволяет блокировать prompt injection, утечки данных и несанкционированные действия. Метрики подтверждают эффективность защиты: BDR = 100%, FPR = 0%.
