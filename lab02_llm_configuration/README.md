# Лабораторная работа №2. Параметры генерации и конфигурация LLM

## Цель работы
Научиться управлять поведением LLM с помощью параметров генерации и системных инструкций, а также экспериментально выбирать конфигурацию модели под конкретную прикладную задачу.

## Используемые технологии
* Python 3.10+
* Библиотеки: `openai`, `pandas`
* Среда выполнения: LM Studio (локальный сервер)
* Модель: `llama-3.2-3b-instruct`

## Описание эксперимента
Скрипт `main.py` выполняет два этапа:
1. **Влияние System Prompt:** один и тот же запрос (анализ события ИБ) отправляется с тремя разными системными инструкциями.
2. **Влияние Temperature:** запрос на генерацию креативных названий отправляется с температурами 0.1, 0.7 и 1.2 (по 2 повтора на каждую).

Все результаты сохранены в файл `results_lab2.csv`.

## Результаты и анализ

### 1. Влияние системного промпта
* **sys_1_базовый (60 сек):** Модель выдала длинный сплошной текст без четкой структуры. Начался "словесный понос", модель смешала русский, английский и даже вставила вьетнамские слова ("xác minhения"). Это показывает, что без ограничений модель тратит много времени и ресурсов впустую.
* **sys_2_структура (39 сек):** Модель разбила ответ на 5 пунктов, указала риски и действия. Однако ответ получился шаблонным (модель 5 раз повторила одну и ту же мысль про "поддельную попытку входа").
* **sys_3_факты_гипотезы (623 сек!):** Модель четко разделила ответ на Факты / Гипотезы / Действия. Это самый качественный ответ, но он занял **более 10 минут**! Модель "зависла", пытаясь вместить все мысли в жесткие рамки. 

**Вывод по этапу 1:** Четкая инструкция (Output Format) критически важна. Она заставляет модель структурировать ответ. Однако для маленьких моделей (3B) слишком сложные инструкции могут привести к огромному времени генерации.

### 2. Влияние Temperature (Генерация названий сервиса)
* **temp=0.1 (стабильно):** Названия предсказуемые (EventScan, Securitas Insights). При повторе (второй запуск) модель выдала другие названия, но в том же строгом деловом стиле.
* **temp=0.7 (баланс):** Появилось разнообразие (ThreatWatch, SecurEye, CyberSentinel). Названия звучат интереснее, но модель все еще держится в рамках темы.
* **temp=1.2 (хаос):** Модель начала смешивать языки. В одном из ответов появилось голландское слово "naam" (имя). Названия стали странными (EventShield, SecurityLogHub), а в конце модель добавила: *"Намногое возможностей для развития этих названий!"* (с ошибкой).

**Вывод по этапу 2:** Для точных задач (ИБ) нужна низкая температура (0.1–0.2). Для креатива — 0.7. Высокая температура (1.2) делает ответы непредсказуемыми, и модель начинает "галлюцинировать" на других языках.

## Итоговая рекомендуемая конфигурация
Для задачи «Первичный анализ события ИБ» (из методички):
* **System Prompt:** `sys_3_факты_гипотезы` (снижает риск галлюцинаций).
* **Temperature:** 0.2 (стабильность).
* **Ограничение длины (max_tokens):** 300–400 токенов. (Обязательно! Иначе модель будет генерировать ответ по 10 минут).

## Общий вывод
В ходе работы я убедилась, что параметры генерации не делают модель умнее, но позволяют управлять её поведением. Системный промпт задает рамки, а температура регулирует креативность. Для задач информационной безопасности предпочтительны строгие промпты, низкая температура и обязательное ограничение длины ответа. Модель Llama 3B склонна к смешению языков и требует контроля.
